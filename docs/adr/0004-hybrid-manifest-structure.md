# ADR 0004: Hybrid Manifest Structure and Persistence

## Status
Accepted

## Context
The application needs to track which conversations have been processed and what notes were generated. We need a system that is performant, resilient to corruption, and transparent to the user (Obsidian-friendly).

## Decision
We will implement a **Hybrid Folder-based Manifest** system located within the Obsidian Vault at `.synapse/manifest/`.

1. **Format**: All manifest files will be in **JSON** for programmatic efficiency, strictness, and native Python support.
2. **Structure**:
    - `version.json`: Tracks `schema_version` and `synapse_tool_version`.
    - `conversations/`: Contains individual JSON files named after the conversation hash (e.g., `[hash].json`).
    - `identity/`: Stores state and history for the user profile.
    - `logs/`: Stores rolling log files generated by the application for audit and debugging.
3. **Atomicity**: Writes will be performed using an atomic pattern (write to temp file, then rename) to prevent data loss.

## Consequences
- **Positive**: High resilience (corruption is localized); Legible to humans; Scalable performance (no large single file to parse); Git-friendly.
- **Negative**: Increases the number of small files in the `.synapse` directory.
